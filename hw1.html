Private key → public key

Elliptic-curve scalar multiplication as a one-way function: computing Q = kG is easy, recovering k from Q is hard (ECDLP). Ethereum uses the curve secp256k1, y² = x³ + 7 over a 256-bit prime field. Here we use the same equation over a tiny field.

2 Computing G, 2G, …, kG

Each row adds G to the previous point: (j+1)G = jG + G. The first step is a doubling (tangent line), the others are additions (secant line).

Faster method: double-and-add

Adding G one step at a time needs k − 1 additions, which is hopeless for a 256-bit key. Double-and-add reads k in binary from the most significant bit: for every bit it doubles the running point R, and when the bit is 1 it also adds G. The number of operations grows with the number of bits of k, about log₂ k, instead of with k itself.

4 Statistical exploration

The experiment is repeated for every private key k = 1 … n − 1, where n is the order of the base point, so each run studies the complete set of public keys that G can produce. The curve mod 17 has only 8 of them, too few for statistics, so the same equation y² = x³ + 7 is also offered over larger primes whose number of points is prime. 5 Discussion

What is meaningful for a one-way function

A one-way function only has to be easy to compute and hard to invert. For Q = kG the hardness does not come from the output looking random: it comes from the size of the group. On the toy curves the statistics look fine (no correlation, near-uniform classes, about half of the bits change) and yet every key is recovered by trying all n − 1 values. On secp256k1 the same search would need about 2²⁵⁶ steps, and the best known algorithms (baby-step giant-step, Pollard's rho) still need about √n ≈ 2¹²⁸. So the statistical tests here are a sanity check, a necessary condition, not a proof of security. What matters is that the output does not leak k in a usable way and that n is large and prime, so that every point other than O generates the whole group.

What belongs to hash functions

The avalanche effect, balanced output bits, fixed-length output and collision resistance are design goals of hash functions like SHA-256 or Keccak-256, which must behave like a random function with no structure. Scalar multiplication is the opposite: it is a group homomorphism, (k₁ + k₂)G = k₁G + k₂G, and the mirror symmetry (n − k)G = −kG shows up in every frequency count. This structure is not a weakness. ECDSA signatures and ECDH key exchange depend on it: in ECDH, a(bG) = b(aG) gives both parties the same secret. The "avalanche-like" change of coordinates seen in 4.5 is a side effect of the addition formulas, not a design goal.

Link to Ethereum

In Ethereum the private key is a 256-bit number k, the public key is Q = kG on secp256k1 (64 bytes, x‖y), and the address is the last 20 bytes of Keccak-256(Q). The pipeline uses both kinds of function: scalar multiplication provides the algebraic link needed for signatures, and the hash adds the properties that kG does not have, producing a short, uniform-looking identifier.
