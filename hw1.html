Scalar multiplication on a toy curve

Elliptic-curve scalar multiplication as a one-way function: computing Q = kG is easy, recovering k from Q is hard (ECDLP). Ethereum uses the curve secp256k1, y² = x³ + 7 over a 256-bit prime field. Here we use the same equation over a tiny field.

1 Curve, base point and private key

Curve y² = x³ + b (mod p), as in secp256k1 where a = 0.

2 Computing G, 2G, …, kG

Each row adds G to the previous point: (j+1)G = jG + G. The first step is a doubling (tangent line), the others are additions (secant line).

Faster method: double-and-add

Adding G one step at a time needs k − 1 additions, which is hopeless for a 256-bit key. Double-and-add reads k in binary from the most significant bit: for every bit it doubles the running point R, and when the bit is 1 it also adds G. The number of operations grows with the number of bits of k, about log₂ k, instead of with k itself.

5 Discussion

What is meaningful for a one-way function

A one-way function only has to be deterministic, easy to compute and hard to invert. For Q = kG the hardness does not come from the output looking random: it comes from the size of the group. On the toy curves the statistics look fine (no correlation, coordinates spread over the range, about half of the bits change) and yet every key is recovered by trying all n − 1 values. On secp256k1 the same search would need about 2²⁵⁶ steps, and the best known algorithms still need about √n ≈ 2¹²⁸. So the statistical tests are a necessary condition, not a proof of security: what matters is that the output does not leak k in a usable way and that n is large.

What belongs to hash functions

The avalanche effect, balanced output bits, fixed-length output and collision resistance are design goals of hash functions like SHA-256 or Keccak-256, which must behave like a random function with no structure. Scalar multiplication is the opposite: it is a group homomorphism, (k₁ + k₂)G = k₁G + k₂G, and it is a bijection on 1 … n − 1, so there is nothing to compress and no collisions. This structure is not a weakness: ECDSA signatures and ECDH key exchange depend on it, for example a(bG) = b(aG) gives two parties the same secret.
